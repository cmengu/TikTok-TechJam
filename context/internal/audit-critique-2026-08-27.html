Section 1

Contradictions with shipped code and the build plan

Resolve these before phase 3. Every later phase emits from this vocabulary and measures with this ladder.

1.1

Event vocabulary: 16 vs 22 vs 25 vs 27

Blocking

Code has 16. The chrono doc's EVENT_TYPES has 22 and schema_version: 2. The audit adds phase_entered, phase_exited, digest (25). The chrono doc's own phase-13 code emits convergence and prediction, which are in nobody's vocabulary (27) — its own assert type in EVENT_TYPES would fail on them.

→

Decided: 33, not 27. Walking every tab and phase found five more (data_profile, research_query, hypothesis_updated, incumbent_changed, llm_call) plus a note valve. schema_version stays 1. Full list in §6.

1.2

Heartbeat routing

Minor

Chrono 2.4 keeps heartbeat in the vocabulary and routes it inside _drain. The shipped decision is the opposite: emit("heartbeat") raises; sidecar only via log.heartbeat().

→

Doc follows code. Drop heartbeat from the vocabulary in the doc.

1.3

Two promotion ladders exist

Blocking

The build plan's §6 (what phase-5 measure.py is built from) uses screen −0.010 / +1·SD(Δ), k=3 means 0.025/0.016, BH q=0.10, t 2.92/2.13/1.83, DiD 0.013/0.007. Chrono phase 11 uses screen +1σ / −0.01, replicate "all three deltas positive AND mean ≥ 0.010", holdout η=0.005, audit at 5σ — no BH, no t-stat, no DiD. The agent will build whichever it reads first.

→

Pick the chrono rule: simpler, honest about its 6–12% false-positive rate, matches the audit's dossier screenshot. Then rewrite the build plan's phase-5 constants to match.

1.4

"Derive thresholds from σ" — then the code hardcodes 0.010

Should fix

Chrono 4.5 says thresholds come from the measured σ. The phase-4 code sets promote_bar: 0.010 as a constant in the same function.

→

promote_bar = max(0.010, 2.5 · sd_delta / √3); log both terms so the report can say which one bound.

1.5

Rung count: 5, 3, or 4 — and where does "full" run?

Blocking

Code has 5 rungs (smoke, screen, full, replicate, holdout). Chrono 11 describes three; 13.7 says "four-rung ladder"; full is used only in calibration. Yet the Replication tab needs screen-versus-full pairs per node, so a full-data run must happen somewhere in the ladder — and phase 11 never says where.

→

Decided: three rungs — smoke, screen, replicate-on-full (3 paired seeds, incumbent side cached). Holdout is not a rung; it is a run-level checkpoint with at most two visits.

1.6

Three LLM calls have no cost slice

Should fix

Slices are researching, coding, training, tuning. Phase 9 verify calls llm_strong.semantic_match; phase 11 adjudicate calls an LLM per link; phase 12 has an adversarial falsifier. None fits. The cost tab's headline claim depends on these being counted.

→

Decided: tokens live only on a new llm_call event whose slice is set by the caller — researcher/brief/adjudicate → researching; coder/verify/debug turns → coding; tuner → tuning. Four slices kept.

1.7

Protocol hash length

Minor

Chrono 0 truncates to 12 hex; shipped code emits sha256:<64 hex>.

→

Fixture and every doc example use the shipped form.

Section 2

Loop edges missing from the diagram and the code

Each of these is described in a sentence of prose somewhere and has no arrow in the loop, no branch in the pseudocode, and no event.

2.1

UNCLEAR attribution has no edge back to the coder

Blocking

11.6: a positive delta with UNCLEAR attribution does not promote; verdict is inconclusive. 11.5: inconclusive nodes requeue at reduced priority. But UNCLEAR is an implementation defect (dead gate, Glorot init), not noise — rerunning the same code with more seeds reproduces the same dead gate. AgentX fixes it with a one-line rewrite in round two. That is an edge 11 → 8 carrying the observable finding, and it does not exist.

→

inconclusive with attribution="unclear" requeues the hypothesis as maturity="probe" with the broken-link report attached as coder context. Noise-inconclusive requeues unchanged. Two different edges.

2.2

No state for a node whose K candidates all failed verify

Should fix

Phase 9 fail_round after three rewrites. The node was created (candidates_generated carries node=18), never ran, has no measurement. None of the nine states fits: not rejected (no measurement), not retired (family alive), not debugging (no failure event).

→

Create the node only after a candidate passes verify. Failed rounds are hypothesis-level events with no node — NOVA's "working state unchanged, round recorded as semantic failure".

2.3

"≥2 independent runs" makes the forbidden list empty by construction

Should fix

12.3 requires two independent runs before an anti-pattern is confirmed. If "run" means a harness run (one 24-hour execution), a hackathon has one or two, nothing is ever confirmed, and the audit's own daily check — "if the forbidden list is empty after fifty attempts, the gates are not admitting anything" — fires on every run.

→

"Run" means node. Confirm at ≥2 nodes in the same family with the same failure signature.

2.4

The adversarial falsifier exists in no diagram, code, slice, or cadence

Minor

12.3 introduces an agent whose only job is to falsify a claimed mechanism. When does it run, on what, at what cost?

→

Decided: cut. Admission is count-based (≥2 nodes); excluded is set by hand via intervention. Revisit Saturday only if everything else is green.

2.5

Tuner trials are runs but are not in the ladder

Should fix

8.6 sends independent knobs to Optuna. Each trial is a phase-10 execution and a screen measurement. Twenty trials on the screen rung is twenty draws from the same null; the best one is exactly the best-of-N artefact phase 4 warns about.

→

A sweep is one node; trials are measurement events with trial=; only the best trial enters replicate, carrying n_trials=20 so the report can discount it.

2.6

Restart / resume is not a phase

Blocking

Chrono 2 says "nothing else holds state", but tree, queue, memory and the tuner study all live in-process. The harness will die at least once overnight. New run or resume? Nothing says.

→

python -m harness resume <run_id> rebuilds tree/queue/memory by reducing events.jsonl — the same fold the app does, which is also the strongest test that the fold is correct — emits intervention if a human triggered it, and reopens the log. The most likely hackathon-night failure; costs one afternoon.

2.7

Holdout arithmetic does not close

Blocking

11.4: five paired seeds, at most twice. Paired = candidate + incumbent = 10 full runs per visit, 20 for two. Phase 4 prices five full baseline runs at ~15 GPU-hours, so one full run ≈ 3 h and the holdout costs ≈ 60 GPU-hours — more than the whole hackathon budget.

→

Decided: holdout leaves the ladder entirely — ≤2 visits per run (first promotion, end), 3 paired seeds, candidate side only, holdout_visits counter enforced in code. A node failing holdout is rejected, never requeued.

2.8

Where search_validation and holdout come from is never said

After webinar

0.5 carves two validation sets; 1.7 says Ali-CCP has no timestamp and the split is at file level. If the organisers ship train/test only, both sets must come out of train — or test doubles as search_validation and holdout comes from train. The two sections never meet.

→

Decide after 28 Aug. Until then write into protocols/aliccp.yaml: search_validation = organisers' test file; holdout = last 10% of train by sample_id, ASSUMED chronological — and hash the assumption.

2.9

The synthetic planted effect sits exactly on the promote bar

Blocking

3.3 plants a true effect of +0.010. Phase 4 says k=3 paired detects ~2.5·SE; 11.3 promotes at mean ≥ 0.010. A true +0.010 effect is promoted about half the time, so the build plan's phase-5 gate (FN=0) is unreachable by design and the scorecard reports ~50% false negatives on a working harness.

→

Plant +0.025 for the strong signal and a second marginal +0.010 feature whose expected promotion rate is stated as "≈50%, by design". Gate on FP=0, FN=0 on the strong signal, leak caught.

2.10

Saturation hashes the field that never changes

Should fix

12.7 hashes discretised architecture fields. 5.7 says architecture is worth ~0.002 here and most hypotheses are features / objective / training. Architecture repeats >80% almost immediately and the run stops on "idea exhaustion" while ideas are still fresh.

→

Signature over (stage, mechanism) keys of the last N hypotheses.

2.11

Exploration reserve uses unseeded randomness

Minor

7.5 random() > explore in a harness whose whole argument is replayability.

→

Seed from protocol.run.seed; emit queue_reordered with explored=True when the reserve fires.

Section 3

Log → app links the audit opens but does not close

The audit adds events for the app to fold over. Several of the folds it promises cannot be built from the events as specified.

3.1

phase_entered with no exit lights a chip forever

Blocking

A worker that dies mid-phase never emits phase_exited. The strip then shows phase 10 "running" for the rest of the night — the opposite of the stuck-loop detection the strip exists for.

→

A phase is open only while its worker's last heartbeat is under 3× the interval; heartbeats carry phase= so the strip can be rebuilt from the sidecar alone; emit phase_exited from a finally: block.

Section 5

Scope honesty

The chrono doc adds four modules the build plan does not have: agents/evidence.py (phase 6), verify.py beyond the rulebook (phase 9), K-candidate coder.py (phase 8), memory.py with admission gates and saturation (phase 12). Together they are roughly the size of existing build phases 6–8 combined. The audit's own line stands: stop after app step 7 and there is a competitive submission.

Order of value per hour, given the ladder and log already exist:

  1. K candidates with deterministic ranking (phase 8 + a cut-down 6 with fixed weights) — the biggest ablation number and the dossier's centrepiece.
  2. verify.py categories B, C, D, F only (columns, protocol touch, anti-pattern regex, observables wired) — regexes, no LLM.
  3. digest + anti_pattern events with the ≥2-node admission rule, no falsifier.
  4. Evidence α-routing and the adversarial falsifier — only if the above is green by Saturday.

Reserve all 27 event types now regardless. A reserved type that is never emitted costs nothing; an unreserved one costs a reducer rebuild.

  • Strict writer, lenient reader: emit rejects unknown types; the reducer ignores and counts them. Adding a type is never breaking.
  • Every event names its subject: node= / hyp= / cand= / worker=. Paths end in _path, relative to run_dir.
  • llm_call.slice set by caller: researcher, brief, adjudicate → researching; coder, verify, debug turns → coding; tuner → tuning. Training is GPU-only.
  • hypothesis_updated.status ∈ backlog · probe · ready · dequeued · spawned · failed_verify · dropped · merged. incumbent_changed.reason ∈ promotion · rollback.

Ladder — chrono rule, four fixes

  • Rungs: smoke → screen → replicate-on-full. Holdout is not a rung.
  • Refuse to search if σfull > 0.02. sd_delta defaults to σ·√2; re-estimate ρ after 3 replicated candidates; emit a band refresh.
  • Screen (1 paired seed, subsample): Δ0 ≥ +1.0·sd_delta → replicate; ≤ −0.010 → rejected; else inconclusive (priority ×0.5, ≤2 revisits, then retired).
  • Replicate (3 paired seeds on full; incumbent's seeds cached): all 3 > 0 and mean ≥ max(0.010, 0.95·sd_deltafull) — one-sided known-σ α = 0.05 at k = 3; with the sign rule ≈3% per-candidate false promotion. Say so in the writeup.
  • mean ≥ 5·sd_deltafull → leak audit first. Attribution CLEAR required; UNCLEAR → hypothesis_updated status=probe with the link report attached.
  • Promote → verdict promoted + incumbent_changed reason=promotion.
  • Holdout: run-level, ≤2 visits (first promotion, end), 3 paired seeds, candidate side only, counter enforced. Report only if ≥ best + 0.005; failing node is rejected reason=holdout, never requeued.
  • Dropped from build plan §6: BH, t-table, DiD, k = 5 tier. Synthetic plants +0.025 strong, +0.010 marginal, 0, leak; gate on strong / noise / leak / holdout_visits < 3.

Lifecycle — three objects, three lifetimes

  • Hypothesis lives in the queue; every status change is hypothesis_updated.
  • Candidate exists only between candidates_generated and candidate_ranked, addressed hyp=, cand=; K candidates, ≤3 rewrite rounds, then failed_verify. No node.
  • Node is born when the ranked winner passes verify: node_created(hyp, cand, parent=incumbent, diff_path). Only nodes have measurements, states, verdicts. Nine states unchanged. Writer rule: node_created must reference a hypothesis currently dequeued.
  • UNCLEAR attribution → probe requeue with the link report in the coder prompt; noise-inconclusive → same hypothesis at ×0.5, no context. Two distinguishable edges.
  • Tuner sweep = one hypothesis → one node; trials are measurement(rung=screen, trial=i); best trial enters replicate carrying n_trials.
  • The dossier's candidates section folds by hyp=, so it renders for hypotheses that never became nodes.

Memory

  • "Run" = node. anti_pattern confirmed at ≥2 nodes, same family, same failure signature; one node = pending. Status ∈ pending · confirmed · excluded; excluded is set by hand via intervention. Falsifier cut.
  • Saturation over (stage, mechanism) of the last 20 hypotheses; stop when repeat rate > 80% for 2 consecutive rounds. Round = one dequeue.
  • Memory tab = fold over anti_pattern + latest digest.

Run mechanics

  • python -m harness resume <run_id>: reduce events.jsonl → tree / queue / memory, reopen the log with seq continuing, emit intervention kind=resume. Optuna study persisted at runs/<id>/tuner.db.
  • Splits until the webinar: search_validation = organisers' test file; holdout = last 10% of train by sample_id, assumption written and hashed. Revisit 28 Aug.
  • Exploration: random.Random(protocol.run.seed); queue_reordered explored=true.
  • Intervention = any human write under runs/<id>/, protocols/, bank.yaml during a run, plus resume; kind=.

App

  • phase_exited in finally:; reducer closes a phase whose worker heartbeat is >3× interval old; heartbeats carry phase=; active_phases keyed by worker, chip shows a worker badge.
  • Ten chips: setup · fan-out · rank · queue · candidates · verify · run · believe · digest · report.
  • GET /runs/{id}/files/{path}, allowlist patches/ reasoning/ observables/; observables as per-seed JSONL, event carries path + first / last / max.
  • semantic_filter = pre-execution (A–F, Z); rule_trip = runtime child violation. Separate histograms.
  • Losers are loose files; the winner's cand{k}.diff is the one file. Fake run scripts "node 18" from audit Part 5 as the JS fixture. Hash route #/run/<id>/node/<n>.

Naming

Events carry loop-phase name= only, never an integer. Tickets say "build phase N" / "loop phase <name>". round = one dequeue. stage = the six pipeline stages only.
