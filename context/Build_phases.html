Beating NISE Build Phases

Eleven phases from an empty repository to a run whose numbers can be believed. Each phase names the only files it may touch, the interfaces it must expose (pseudocode, never final code), the tests that must pass before the next phase starts, and what it hands forward. Written to be executed one phase at a time by a smaller model.

Rules for every phase · The seam: types.py · Fixed vocabularies

Rules for every phase

These hold in every phase below. The implementer reads them once and re-reads them at the start of each phase.

  1. Touch only the files listed under "In scope". If the work seems to need a change elsewhere, stop and report the need; do not make the change. The only exception is a test file for the current phase.
  2. harness/types.py changes are their own pull request, reviewed by both people. A phase that needs a new field on a dataclass proposes it as a diff and waits.
  3. Tests run offline, on CPU, with no LLM and no GPU. Every phase's test suite finishes in under 60 seconds, except tests marked slow, which may take a few minutes and run on the synthetic task only.
  4. Regression is part of the gate. "Tests pass" means the whole tests/ directory, including every earlier phase, not just the new file.
  5. No invented numbers. Every threshold in measurement comes from the ladder locked in the Audit Redline §6 (27 Aug) and is a named constant with a comment giving the rule. Every event type, node state and file name comes from the vocabularies at the end of this page.
  6. Judgement lives in the bottom layer only (§0): protocol, measurement, and the frozen values. Agents propose; the runner executes; the harness decides. No module reads another module's state — every module reports to events.py.
  7. Stack: Python 3.11+, pytest, pyyaml, pyarrow, torch (CPU wheel), fastapi + uvicorn + httpx (phase 2), optuna==4.9.* (phase 7), polars (phase 8). Nothing else without a stated reason.
  8. Each phase ends with a commit whose message is the phase title and a short note of anything left unresolved. Person A / B ownership follows the split in Harness Decisions §A.

The seam: types.py

Four dataclasses that every other file passes around. They are fully fielded in phase 0 because they are the contract between the two people; later phases may add fields only through the rule above. Field names are the product spec's.

Stage   = Literal["data","features","objective","architecture","training","ensemble"]
State   = Literal["screening","running","replicating","promoted","inconclusive",
                  "rejected","retired","leaked","debugging"]
Rung    = Literal["smoke","screen","full","replicate","holdout"]   # full = seed-0 full-data run, replicate = seeds 1,2 on the same data; holdout is NOT a ladder rung

@dataclass Hypothesis:
    id: str; stage: Stage; mechanism: str          # family = f"{stage}/{mechanism}"
    description: str; citation: str | "no prior"
    expected_gain: float; expected_gpu_h: float
    parent_node: int | None; patch: Path | None    # patch only for hand-written ones (phase 6)

@dataclass Node:
    id: int; parent: int | None; hypothesis_id: str; commit: str | None
    state: State; rung: Rung; kind: Literal["draft","improve","debug","ablate","trial","ensemble"]
    scores: dict[str, list[float]]                # metric -> per-seed scores, parallel to seeds
    seeds: list[int]; cost: Cost; created_seq: int

@dataclass RunResult:
    node: int; attempt: int; seed: int; rung: Rung; ok: bool
    metrics: dict[str, float]; failure_class: str | None; stderr_tail: str
    gpu_s: float; wall_s: float; result_path: Path | None; checkpoint_path: Path | None

@dataclass Verdict:
    node: int; rung: Rung; state: State; metric: str
    delta_mean: float | None; delta_per_seed: list[float]; band: tuple[float,float]
    reason: str                                   # becomes the event's summary
    rule_trips: list[str]

@dataclass Cost: gpu_s: float; tokens_in: int; tokens_out: int
                 slice: Literal["researching","coding","training","tuning"]

In scope

@dataclass Protocol: task: str; schema_version: int; ruler: dict; run: dict; protocol_hash: str; path: Path
def load(path) -> Protocol             # validates required keys; nulls allowed under ruler
def canonical_bytes(ruler: dict) -> bytes
    # sort keys recursively; floats via repr of float(x) so 0.10 == 0.1; ints stay ints;
    # None -> "null"; no whitespace; utf-8. Comments never reach here (yaml drops them).
def protocol_hash(ruler: dict) -> str  # "sha256:" + hex of canonical_bytes; run block NOT included

# harness/events.py
class EventLog:
    def __init__(self, run_dir: Path, run_id: str, protocol: Protocol): ...
        # opens events.jsonl and heartbeat.jsonl for append; starts one writer thread
        # first line written is run_started with the whole protocol dict embedded
    def emit(self, type: str, **fields) -> int
        # validates type in EVENT_TYPES and fields.get("state") in STATES if present;
        # requires "summary" (str); stamps schema_version=1, seq, t (ISO-8601 UTC), run, protocol_hash;
        # puts on queue; returns the seq it WILL get (allocated under a lock, so monotonic)
    def new_node(self, parent: int | None) -> int      # one counter, lock-protected
    def heartbeat(self, worker: str, **fields) -> None # goes to heartbeat.jsonl through the same queue
    def close(self) -> None                            # drains, fsyncs, joins thread; emit after close raises
    # writer thread: json.dumps(line) + "\n"; flush() every line; os.fsync only when type in
    # {"verdict","submission_written","run_ended"}
# python -m harness init protocols/synthetic.yaml
#   -> creates runs/<task>-<YYYYMMDD-HHMMSS>/ , writes run_started, closes, prints the run id and hash

Phase 2 · Fake run, server, and the first three views

Owner B, days 1–2Depends on phase 1Source §4 "How the log reaches the frontend"

Goal

A scripted stream of every event type, written through the real EventLog, replayed through a real server, rendered by a reducer in the browser. From here on, every backend phase is watched through this app, and the frontend can be finished without waiting for the backend.

In scope

harness/fake_run.py, app/server.py, app/static/index.html, app/static/reducer.js, app/static/app.js, tests/test_02_fake_run.py, tests/test_02_server.py, app/static/reducer.test.js.

Out of scope

Any view beyond Run tree, Hypotheses, Now running. Audit endpoints (phase 9). Styling beyond legibility. Any state kept in the browser that is not the output of reduce. WebSockets or a message broker.

Interfaces

# harness/fake_run.py
SCRIPT: list[dict]   # ~200 events, hand-authored in code, in this order:
  run_started (by EventLog) → hypothesis_queued ×6 (two per stage: features, training, objective)
  → node_created(kind=draft) → state_changed screening→running → heartbeat ×n → measurement
  → verdict (state=inconclusive) → node_created → … → failure(class=cuda_oom) → recovery
  → verdict(state=rejected) → rule_trip → research_source ×3 → cache_lookup(hit=false)
  → cache_lookup(hit=true, confirmed=true) → queue_reordered → verdict(state=replicating)
  → verdict(state=promoted) → submission_written → intervention → run_ended
  Every node referenced by a later event is created first. Every state_changed is a legal transition
  (table in phase 6; for now: screening→running→{replicating,inconclusive,rejected,debugging},
  replicating→{promoted,inconclusive,rejected,leaked}, debugging→{running,retired}, *→retired).
def write(run_dir, speed: float = 20.0, instant: bool = False) -> str   # returns run id
# CLI: python -m harness fake [--instant] [--speed 20]

# app/server.py  (FastAPI)
GET /runs                                  -> [{run_id, task, protocol_hash, started}] from runs/*/events.jsonl line 1
GET /runs/{id}/events?since=0&stream=true  -> SSE: replay lines with seq>since, then tail (poll 0.5 s)
GET /runs/{id}/events?since=0&stream=false -> JSON array of lines with seq>since (polling fallback)
GET /runs/{id}/heartbeat?since=0           -> same two shapes over heartbeat.jsonl
unknown id -> 404

# app/static/reducer.js  (pure; no DOM; ES module so node's test runner can import it)
export const initial = () => ({run:null, nodes:{}, queue:[], workers:{}, verdicts:[], lastSeq:0})
export function reduce(state, ev) -> newState    # never mutates input; switch on ev.type
  run_started       -> state.run = {id, protocol_hash, task}
  node_created      -> nodes[id] = {id, parent, state:"screening", kind, scores:{}, seeds:[]}
  state_changed     -> nodes[id].state = ev.state
  hypothesis_queued -> queue.push({...})
  queue_reordered   -> queue = ev.order.map(id -> existing entry)
  heartbeat         -> workers[ev.worker] = ev  (latest only)
  verdict           -> verdicts.push(ev); nodes[id].state = ev.state; scores/seeds appended
  everything else   -> unchanged (kept for later views)
  always            -> lastSeq = ev.seq

# app/static/app.js: EventSource(`/runs/${id}/events?since=${lastSeq}`); on message reduce + render;
# on error reconnect with the remembered lastSeq. Three renders: tree (indent by parent), queue (ordered list), workers.

Phase 4 · Runner

Owner ADepends on phases 1, 3 (B watches through phase 2's app)Source §5

Goal

Spawn the candidate as a child process, enforce a timeout, classify a failure from exit code and stderr together, recover per class, heartbeat, and return a RunResult. The runner trains nothing and decides nothing.

In scope

harness/runner.py, tests/test_04_runner.py.

Out of scope

Which node to run next. Any judgement on the metrics. The SSH backend (the Backend seam exists; only LocalBackend is implemented). The derived-timeout calibration loop — the formula is implemented, the inputs are passed in.

Interfaces

class Backend(Protocol):
    def run(self, workspace: Path, cmd: list[str], env: dict, timeout_s: float,
            on_progress: Callable[[dict], None]) -> Completed   # returncode, stderr_tail, wall_s
class LocalBackend: subprocess.Popen; polls WORKSPACE/progress.jsonl every 1 s and calls on_progress per new line

FAILURE_CLASSES = ("cuda_oom","host_oom","diverged","timeout","contract_violation","crash")
RECOVERY = {                      # applied to env for attempt 2; None = no retry, hand back to tree
  "cuda_oom": lambda env: {**env, "BATCH": str(int(env["BATCH"]) // 2)},
  "host_oom": lambda env: {**env, "LOADER_WORKERS": "0"},
  "diverged": lambda env: {**env, "LR": str(float(env["LR"]) / 2)},
  "timeout": None, "contract_violation": None, "crash": None }

def derived_timeout(seconds_per_row_screen, rows, epochs, safety=2.0, floor_s=60) -> float
def classify(returncode, stderr_tail, progress: list[dict], result_path) -> str | None
    # order: NaN or loss > 10× first loss in progress → diverged
    #        "CUDA out of memory" in stderr → cuda_oom
    #        returncode == 137 (or -9) and stderr_tail empty → host_oom
    #        killed by us at deadline → timeout
    #        returncode == 0 and (no result.json or missing metric keys) → contract_violation
    #        returncode != 0 → crash;  else None (ok)

class Runner:
    def __init__(self, events: EventLog, task: Task, run_cfg: dict, backend: Backend = LocalBackend(),
                 heartbeat_s: float = 30.0): ...
    def run(self, node: Node, rung: Rung, seed: int, timeout_s: float, env_overrides: dict = {},
            attempt: int = 1) -> RunResult
        # env = {DEVICE, SEED, WORKSPACE, BATCH, LR, EPOCHS, FEATURES} + task.candidate_env(paths) + overrides
        # if DEVICE == cuda: CUDA_VISIBLE_DEVICES = worker gpu index
        # workspace = runs/<id>/workspace checked out at node.commit (phase 6 sets commit; here a plain dir)
        # emits heartbeat every heartbeat_s with {node, step, total, loss}; kills on diverged
        # on failure: emit failure{node, attempt, class, stderr_tail}; if RECOVERY[class]: emit recovery and
        #   recurse with attempt=2 (max 2); cost of attempt 1 stays on the node
        # on ok: metrics = task.score(result.preds, "search"); return RunResult(ok=True, …)

Phase 5 · Measurement

Owner A (numbers); B builds the Replication view off the verdict eventsDepends on phases 3, 4Source Harness Decisions (chronological) phases 4 and 11, as fixed by the Audit Redline §6 "Ladder" — 27 Aug 2026

Goal

Everything that decides whether a number is believed, as pure functions on numbers first, then one class that emits verdicts. The synthetic scorecard must show zero false promotions, the planted +0.025 promoted, the planted +0.010 never rejected, and the planted leak caught — before any GPU hour is spent.

The ladder, in one paragraph. Three rungs: smoke (60 s contract check, no score), screen (one paired seed on the training subsample, full search-validation), replicate (three paired seeds on the full training set; the incumbent's full-rung scores for seeds 0–2 are cached from its own promotion, so it costs three candidate runs). A candidate leaves the screen if its paired delta clears one screen-noise band; it is promoted if all three full-rung deltas are positive and their mean clears a bar derived from the full-rung noise, and attribution is clear. Holdout is not a rung. It is a run-level checkpoint visited at most twice — at the first promotion and at the end — with three paired seeds on the candidate side only, and it decides the reported number, never the incumbent.

In scope

harness/measure.py, tests/test_05_measure_pure.py, tests/test_05_scorecard.py (marked slow).

Out of scope

Choosing what to run next (phase 6 decides rung progression; measure only returns the verdict for the rung it is given). Attribution adjudication itself (phase 7 — measure only reads the label it is handed). The three remaining leak post-checks (phase 10). Bootstrap intervals, Benjamini–Hochberg, Student-t tables, difference-in-differences — all removed from the design on 27 Aug; do not reintroduce them.
