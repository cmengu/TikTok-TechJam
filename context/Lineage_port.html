Porting is the wrong verb. NOVA's trajectory memory, its accumulated forbidden patterns, and AgentX's falsifiable-attribution brake all have working implementations in this repo already. None of the three currently affects a single decision the agent makes. One is broken by a field-name mismatch between the code that writes it and the code that reads it, one is pinned open by a hardcoded constant, and one is a data file that no production module loads.

Two claims in the current plan do not survive checking. The AgentX paper contains no statistic about the share of failures that were infrastructure rather than reasoning — that number should not go in a judged write-up. And NOVA's headline pass rates read differently in the abstract than in the results table, so quote the abstract and leave it there.

What the deep read does buy is the correct vocabulary for what we built, and one abstraction — NOVA's architecture gradient — that the queue implements exactly one third of.

SOURCE

What the two papers actually are

Both were pulled from arXiv directly rather than taken from the plan's summary. Titles, authorship and abstracts match what Plan_delta claims, and the implementation detail below comes from the papers' own body sections.

PaperWhoWhat it isLoop unit

2606.27243		 Tencent, 20 authors A verification-aware harness that searches production recommender architectures under a fixed offline-evaluation budget One round = K candidates → filter → verify → rank → train one
AgentX
2606.26859		 Kuaishou, 62 authors A deployed four-stage multi-agent system that generates, implements, A/B-tests and learns from recommendation experiments, plus a layer that rewrites its own agents One cycle = idea → code → online rollout → knowledge asset

The size difference matters for how much of each transfers. NOVA is a search algorithm with a verification cascade bolted to it — that is structurally the same object as our tree, and most of it ports. AgentX is a production organisation: traffic buckets, guardrail vetoes, business-domain metric ownership, three worker instances running for three weeks. Only two of its ideas are separable from that scale, and they are the two we already half-built.

Numbers worth quoting, and one to avoid

NOVA reports production A/B gains of +1.25%, +1.70% and +2.02% GMV across three pCVR objectives at 5% traffic, with absolute pCVR bias falling 58.8%, 66.7% and 37.3%. Its offline metric is effective pass rate, defined as the share of generated candidates that achieve a positive AUC improvement:

NOVA, eq. 12 EPR = N₊ / N_g = LPR · (1 − SFR)
N₊ = candidates with positive ΔAUC · N_g = candidates generated
Landing pass rate times one minus semantic failure rate. The decomposition is the useful part: it separates “the agent wrote code that runs and lands” from “the code was semantically valid for a recommender”, which are the two different ways an autonomous round gets wasted. Our event log already distinguishes these — failure versus rule_trip — so EPR is computable from our own log with no new instrumentation.

The abstract gives 53.3% on ScaleUp and 51.7% on Literature-to-Production against a five-baseline field that includes a human expert loop, ReActAgent, OpenHands and Optuna-TPE. My read of the results table returned different figures for the same rows, which most likely means the table is broken out by a setting the abstract collapses. Quote the abstract's numbers and don't cite the table until someone reads the PDF properly.

AgentX reports 374 ideas producing 10 launchable rollouts over three weeks across three workers, 8× concurrency and 3.7× business value against a manual engineer, and a 0.561% user app-time gain. It does not report what fraction of failures were infrastructure rather than agent reasoning. Plan_delta §6 attributes a “>90% infrastructure” finding to this paper; I could not locate it, and the paper's only failure-taxonomy content is the mechanism of its classifier, not a distribution. The design conclusion §6 draws is still right — it just has to be argued from our own log instead of borrowed.

NOVA

The round, and the gradient

NOVA's Algorithm 1 runs seven stages per round. Read it next to Tree.step() and the correspondence is close enough to be uncomfortable — we arrived at nearly the same shape independently.

1 · Propose
K candidates conditioned on the current architecture, the gradient g_t, and trajectory memory H.
2 · Filter
Drop anything violating hard constraints Ω or a forbidden direction — before building a model at all. Pure text-level rejection.
3 · Verify
The cascade: V_sem (semantic) then V_loc (local executability). Survivors advance to training.
4 · Select
Rank survivors before training by gradient alignment, history, and constraint margin. Pick one.
5 · Apply
Apply the modification. In Copilot mode a human confirms; in autonomous mode it does not.
6 · Evaluate
Train on the full dataset, compute ΔJ against the previous round's AUC.
7 · Update
Append (e*, V, ΔJ) to H; recompute the gradient for the next round.

Termination is a budget of N rounds or a convergence test on offline AUC improvement — the same two-clause rule the TechJam organizers impose on us, arrived at for the same reason. When every candidate in a round is rejected before training, NOVA does not stall: it feeds a negative sentinel ΔJ into the gradient and continues, which is worth copying verbatim because a round of all-rejections is exactly the case where a naive loop wedges.

The architecture gradient is the idea worth stealing

NOVA, eq. 5 g_t = Grad(e_{t−1}, V_t, ΔJ_t, H_t)
A non-differentiable update signal built from the last modification, its verification diagnostics, its measured metric change, and the whole trajectory so far. It is not a number. It carries three named fields.
  • Weak components — which parts of the current architecture are responsible for the bottleneck.
  • Modification directions — which families should be explored next.
  • Forbidden directions — patterns that previously failed, were semantically invalid, or repeatedly went negative.

Our equivalent is family_stats() folded over the event log and consumed by Queue.score_hyp() at harness/tree.py:192. It computes per-family mean Δ, standard deviation and mean cost, and ranks by (mean_delta + sd) / cost. That is a real implementation of modification directions and it works. The other two fields have no implementation. Nothing in the harness ever concludes “the embedding table is the bottleneck”, and nothing ever writes down “stop proposing user-side first-order features”. Both absences are cheap to close, and the second one is the single highest-value change on this page.

One inherited design that should not transfer is stage 4. NOVA ranks candidates before training because training is the expensive step; the ranking exists to avoid spending it. On KuaiRand-Pure a full training run is forty seconds on one CPU core, so pre-training ranking spends LLM tokens — which the judges score — to avoid spending something nearly free. Worse, it violates the rule we borrowed from the other paper: asking a model to rank untested candidates is asking it to be right about a numerical fact. Generate three, run all three, keep the best measured.

AGENTX

Four stages, and the brake

AgentX closes a loop that starts at an under-specified business intent and ends at a knowledge asset. Brainstorm turns intent into ranked, executable proposals; Developing turns a proposal into production code under repository-grounded verification; Evaluation runs a guarded A/B and converts the outcome — win or loss — into a structured, indexed asset; and SGPO rewrites the agents themselves from execution traces.

Most of that presupposes a production surface we do not have. Two pieces do not.

Falsifiable attribution

Before writing any code, AgentX's model-developing agent declares the target change, the causal mechanism it claims, and a set of expected observables with names and healthy-versus-pathological thresholds. After the run, a final review adjudicates each link in that causal chain. All links verified gives CLEAR; any broken or unclear link gives UNCLEAR — and an UNCLEAR gain is not recorded at all, however good the number is.

The paper's own example is the sharpest argument for it: a reproduced RankMixer gate delivered +0.0003 AUC, but the declared observable showed near-zero gate activation for the whole run. The mechanism had not fired, so the gain was not attributable to the change, so it was discarded. A later residual fix produced +0.0022 with every link verified, and that one was kept. This is a brake on exactly the failure our ε = 0.002 convergence rule makes dangerous: a noise-driven improvement that resets the stall counter and sends the search down a family that does nothing.

The eight-dimension code score, and what it implies

AgentX, coding quality Q_code = 0.06·s₁ + 0.12·s₂ + 0.22·s₃ + 0.08·s₄ + 0.06·s₅ + 0.18·s₆ + 0.18·s₇ + 0.10·s₈
The three copper terms are attribute hallucination, correctness-loop iterations, and manual operator interventions — 58% of the weight on the three failure modes that most threaten autonomous operation. Note the third: Kuaishou scores its own agent on human intervention count, and so does the TechJam rubric under Impact & Relevance. Our intervention event already exists in the log for exactly this.

The rule the plan already quotes — “an LLM is permitted to be wrong only on judgment; every objective fact is produced by deterministic code” — is load-bearing throughout the paper, not a slogan. Feature attributes are queried from a schema tool rather than recalled. Metrics are regex-parsed out of raw training logs rather than read by a model. Failure classification is a pure function over the log head and tail. Causal attribution is deterministic link-checking. That is four separate places where they refused to let a model produce a fact, and it is the strongest single thing we can say under a criterion judged on reasoning.

SGPO — evolving the agent prompts from execution traces, admitting an edit only when a paired replay on identical tasks improves the score by more than ε — is genuinely elegant and genuinely out of scope. It needs a corpus of past traces we do not have and five evolution rounds we cannot afford in two days. Plan_delta declines it and should keep declining it.

PORT

Three wires already in the wall

Reading the papers against the code rather than against the plan turns up three mechanisms that exist, are tested, and are disconnected from every decision the loop makes. None of them is a rewrite. Together they are about two hours.

W1

Trajectory memory reaches the proposer blank

Break

This is NOVA's H, and we built it. Tree._append_lesson writes one JSONL row per full-rung seed with the node id, the family, the measured delta, the cost and a diff summary. __main__.py loads the last thirty rows and hands them to propose(). The proposer then renders each row as l.get('heading', 'lesson') and l.get('text', '') — two keys that _append_lesson never writes.

Writesharness/tree.py:432–448 → {node, family, delta, gpu_min, diff_summary} Readsharness/agents/researcher.py:165–167 → {heading, text} Effectevery lesson renders as the literal string "- lesson: " with no content

So the entire Lessons block of the researcher prompt is thirty identical empty bullets. Family stats reach the prompt correctly and do real work; the lessons channel carries nothing. Second defect on the same wire: _append_lesson is only reached after the if not res.ok early return at tree.py:678, so failed runs never produce a lesson at all — which is precisely the half NOVA uses to build forbidden directions.

Fix both together. Have _append_lesson emit a heading and text alongside the structured fields, and call it on the failure path with the failure class as the heading.

Cost~20 minutesBuysthe mechanism §5 already claims we have
W2

The attribution brake is built and pinned open

Pinned

AgentX's CLEAR/UNCLEAR adjudication is fully implemented in measure.py. The ladder accepts an attribution argument, and at line 398 an "unclear" value refuses promotion with the reason “replicate pass but attribution unclear”, writing the value into the verdict payload for the log. The brake works.

Consumerharness/measure.py:341, 398–402, 438 — refuses promotion, records the reason Producerharness/tree.py:51 — ATTRIBUTION_HAND = "clear", passed as the default at :356 Effectevery node in every run is CLEAR by construction; the branch at :398 is dead

The constant was right for hand-written patches in phase 6, where the mechanism was known because a human wrote it. It is wrong for an autonomous run, and the artifact that makes it computable is already specified: the plan's own “declare the observables a change should move, then refuse to credit a gain that did not move them.” For the top-ranked KuaiRand hypothesis this is nearly free — swapping pointwise log-loss for a pairwise or listwise objective predicts that GAUC moves more than nDCG@5 and that training log-loss gets worse while primary improves. Both quantities are already computed.

Add an optional observables field to Hypothesis, have the coder declare it, check it after the replicate rung, and pass "unclear" when a declared observable did not move. The consumer needs no change whatsoever.

Cost~1 hourBuysthe strongest available answer to “why did that work?”
W3

Forbidden patterns have a schema and no reader

No consumer

candidate/rules.jsonl holds seven contract rules, each with an id, a natural-language statement, a check mode of static or llm, a regex pattern, a severity, and — the telling field — "source": "seed". That last key only makes sense if something was meant to append rules with a different source. Nothing does. The only module that reads the file is a test.

Filecandidate/rules.jsonl — 7 rules, all source:"seed", growth-ready schema Checkerharness/agents/contract.py — hardcodes FORBIDDEN_PATH_FRAGMENTS and 5 regexes Readerstests/test_03_synthetic.py:207 only

NOVA earns its forbidden list the hard way, over thousands of production rounds. We get to skip that: the organizers published theirs before iteration zero — static features are flat, capacity is flat, and anything constant within a user contributes exactly zero. That is a populated trajectory memory sitting in a README, and it belongs in this file as seed rules, not in a prompt paragraph where the agent can talk itself past it.

Two changes, in order. Have contract.py load rules.jsonl instead of hardcoding, so the checker can grow. Then append the organizers' dead ends as rules and let confirmed contract violations append themselves with source: "learned". The second half is the mechanism §5 rates as gaining value under a tight iteration budget — with three failures of runway there is no time to rediscover a failure twice.

Cost~40 minutesBuysa checker that grows, and NOVA's best story told with our own file
SCORE

Re-scoring every transfer against the papers

The plan's §5 table was written from the abstracts. Here is the same list re-judged against the body sections, with the KuaiRand cost structure applied.

Verification cascade
NOVA stage 3 — V_sem then V_loc
Keep · restated
The paper's own design defends ours. NOVA's semantic gate is explicitly a hybrid of seed rules, accumulated forbidden patterns and LLM-assisted checks — the same static-plus-llm split rules.jsonl already encodes. It also declines to reject when a case is uncovered, deferring to evaluation rather than guessing. Copy that restraint. The justification changes though: it no longer saves compute, it saves an iteration, and iterations are the budget.
Trajectory memory
NOVA H, eq. 5 — three fields
Keep · one third built
Modification directions work — that is family_stats into score_hyp. Forbidden directions are W3. Weak components are absent and probably should stay absent: identifying the bottleneck component is meaningful when the architecture is a large production graph, and near-meaningless for a hand-written factorization machine with five feature fields.
Negative-sentinel gradient
NOVA — all-K-rejected rounds
Add · new
Not in the plan and it should be. When every candidate is rejected before training, NOVA writes a negative sentinel ΔJ and keeps going. Our loop has never been run end-to-end against real data, and an all-rejections round is the most likely way it wedges on the night of the 31st.
K candidates, ranked pre-training
NOVA stage 4
Cut · confirmed
The pivot breaks this one, and the paper explains why. Stage 4 exists to avoid spending a training run. Ours costs forty seconds and is not scored; tokens are. Generate three, evaluate all three, keep the measured winner — and note that pre-training ranking would also violate the AgentX rule below.
Deterministic facts only
AgentX §5.2 — four separate refusals
Keep absolute
Stronger than the plan states. It is not one principle but four enforcement points: schema query instead of recall, regex log parsing instead of interpretation, pure-function failure classification, deterministic link-checking for attribution. We implement three. The fourth is W2.
Falsifiable attribution
AgentX — declared observables, CLEAR/UNCLEAR
Promote · half built
Parked as optional in §5; it is W2 and the consumer is finished. Under a convergence rule that a single noise-driven win can reset, refusing to credit an unexplained gain is not a nicety — it is what stops the search committing to a family that does nothing.
Failure classifier and retry table
AgentX — pure-function classifier
Keep · re-argue
Transfers intact, but not on the borrowed statistic. The paper gives the mechanism, including the nice detail that infrastructure symptoms are evaluated last so they cannot mask a schema bug. It does not give the 90% figure §6 cites. Our own log measures our own rate — report that instead.
SGPO harness evolution
AgentX — semantic gradients on prompts
Decline · confirmed
Right call, and the paper shows why it is expensive. Five evolution rounds on the brainstorm agent alone, each gated by a paired replay on identical tasks. It needs a trace corpus and a replay harness we would be building from zero.

What this changes in the plan

Ordered by value per minute, and all of it sits inside the 30 August slot the pivot read already reserved for re-pointing the task layer. Nothing here competes with merging the four open PRs or reproducing the baseline — those still come first.

1

Strike the unsourced statistic

Remove the “>90% of loop failures were infrastructure” attribution from Plan_delta §6 and from any draft of the write-up. Replace it with the rate measured from our own failure events during the real run — which is a better claim anyway, because it is ours. Two minutes, and it is the only item here with downside risk if skipped.

2

Reconnect the lessons wire (W1)

Emit heading and text from _append_lesson, and call it on the failure path. Twenty minutes, and it activates the one mechanism the plan most confidently claims to have.

3

Make the contract checker load its own rules (W3)

Point contract.py at rules.jsonl, restate the seven rules for within-user ranking on long_view, and add the organizers' three published dead ends as seed rules. This merges with the rules.jsonl rewrite the pivot read already scheduled, so the marginal cost is small.

4

Unpin attribution (W2)

Add observables to Hypothesis, check them after the replicate rung, pass "unclear" when a declared observable did not move. One hour, no change to measure.py, and it is the page's best Innovation material.

5

Add the negative sentinel

When a round rejects every candidate before training, record a negative-sentinel delta and continue rather than falling through. Cheap insurance against the loop wedging on its first real run.

The sentence to lead the write-up with

Not “we implemented NOVA and AgentX”. The honest and stronger claim is that both systems spend their machinery buying back an evaluation that costs GPU-hours and, eventually, live traffic — and that on this task an evaluation costs forty seconds, so every mechanism had to be re-argued against a budget denominated in iterations and tokens instead. Some survived with new justifications, one was cut outright, and one was promoted from optional to load-bearing. That reasoning is the deliverable for a criterion judged on reasoning.
